# 계산기 Feature Flag 기반 A/B 테스트 계획서

## 1. 실험 목적

기존 계산기(A 그룹)와 개선된 계산기(B 그룹)의 사용성을 비교한다.

B 그룹에는 화면 내 입력 오류 안내와 계산 결과 복사 기능을 추가하였다.

두 그룹의 사용 데이터를 수집하여 개선된 기능이 계산 성공률과 사용자 편의성에 긍정적인 영향을 주는지 확인한다.

## 2. 실험 기간

- 시작일: 2026년 11월 26일
- 종료일: 2026년 12월 10일
- 운영 기간: 14일

실제 운영 시작일과 종료일은 실제 테스트 진행 상황에 맞춰 기록한다.

## 3. 실험 대상 및 그룹

| 구분 | A 그룹 | B 그룹 |
|---|---|---|
| 사용자 배정 | 50% | 50% |
| 계산 기능 | 기존 계산기 | 기존 계산기 |
| 입력 오류 안내 | 브라우저 경고창 | 화면 내 오류 메시지 |
| 결과 복사 | 제공하지 않음 | 제공 |
| 이벤트 기록 | 사용 | 사용 |

## 4. 측정 지표

### 4.1 계산 성공률

계산 성공률 = 성공한 계산 횟수 / 전체 계산 시도 횟수 × 100

### 4.2 입력 오류율

입력 오류율 = 입력 오류 이벤트 수 / 전체 계산 시도 횟수 × 100

### 4.3 평균 계산 소요 시간

계산 시작부터 계산 성공까지 걸린 시간을 측정한다.

### 4.4 결과 복사 사용률

결과 복사 사용률 = 결과 복사 이벤트 수 / 성공한 계산 횟수 × 100

### 4.5 사용자 만족도

사용자 피드백과 만족도 평가를 수집하여 기능의 편의성을 비교한다.

## 5. 데이터 수집 방법

브라우저의 LocalStorage에 사용자 ID, A/B 그룹, 이벤트 종류, 세부 정보, 발생 시간을 저장한다.

실험 로그는 JSON 파일로 다운로드하여 보관한다.

사용자 ID를 기준으로 중복 사용자를 구분하고, 페이지 새로고침에 따른 반복 배정 이벤트는 별도 사용자로 계산하지 않는다.

## 6. 데이터 구분

- LLM 페르소나 10명의 피드백: 모의 사용자 피드백
- 기능 검증 로그: 기능 작동 확인용 데이터
- 2주간 수집한 로그: 실제 실험 데이터

모의 데이터와 기능 검증 데이터는 실제 실험 성과 분석에 포함하지 않는다.

## 7. 실험 결과 판단 기준

B 그룹의 계산 성공률과 사용자 만족도가 A 그룹보다 높고, 계산 소요 시간 및 입력 오류율이 개선되었다면 Persevere를 고려한다.

반대로 개선 효과가 부족하거나 사용 편의성이 낮아졌다면 Pivot을 고려한다.

최종 결정은 2주간 수집한 실제 데이터와 사용자 피드백을 바탕으로 내린다.
